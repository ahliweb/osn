# Release v1.1.0 — 2026-09-05

Toolchain and dependency modernisation, plus one long-standing enforcement
gap closed. **No curriculum content, schema shape or CLI behaviour
changed** — the corpus is byte-identical to v1.0.0, and every command
behaves exactly as it did.

If you are adopting this project for the first time, read
[`docs/releases/v1.0.0.md`](v1.0.0.md) instead; this document only covers
what moved between v1.0.0 and v1.1.0.

## Upgrade notes

None. There are no breaking changes, no data migration, and no command or
flag changed. Pull the tag, run `bun install`, and everything works as
before.

The version is `minor` rather than `patch` only because Zod 4's inferred
types differ subtly from Zod 3's, and the exported schemas are this library
layer's public surface.

### New command

```sh
bun run assist:check
```

Enforces Biome's import organization. It runs `biome check` with the
formatter and linter disabled, so a failure is unambiguously about import
order and is not conflated with the existing `format:check` and `lint`
steps. It runs in CI as its own step.

## Why these upgrades needed more than a green test run

A passing suite is weak evidence for a validation-library or compiler
change, because both can fail *permissively* — becoming more accepting
while every happy-path test still passes. Each upgrade was therefore probed
against the behaviour that actually matters:

**Zod 4** — the https URL validator still rejects `http:`, `javascript:`,
malformed input and the empty string; `parseDataFile` still reports every
issue at once rather than the first, and still names the offending source
file; the learning-record guard still rejects all five identifier-injection
vectors (unknown key, top-level `email`, nested `nisn`, an identifier
inside an array element, and an email-shaped `learnerRef`).

**TypeScript 7** — the failure mode for a compiler rewrite is a strict
option being *accepted but ignored*, which would silently remove type
safety while CI stayed green. Probed directly: indexing a `string[]` and
assigning to `string` still errors, so `noUncheckedIndexedAccess` is live.

**Biome 2** — the five findings from its expanded recommended rule set were
fixed in the code. No rule was disabled and no suppression was added. The
three `noUselessEscapeInString` fixes were verified character-identical, so
no user-facing message changed.

## Two gaps found and closed

**An import standard nothing enforced.** `biome.json` had declared
organize-imports on since the project began, but neither `format:check` nor
`lint` runs Biome's assist actions — only `biome check` does. 36 of 137
files had unsorted imports. Now applied and enforced in CI.

**Dependabot lockfile drift.** The `npm` ecosystem updates `package.json`
without touching `bun.lock`, so *every* dependency pull request failed CI
on `--frozen-lockfile` and needed a manual regeneration. Switched to the
`bun` ecosystem, which maintains the lockfile itself.

Relaxing `--frozen-lockfile` would have made all three failing pull
requests pass in one line, and was rejected: reproducible installs are a
supply-chain control (RISK-05 in
[`docs/governance/security.md`](../governance/security.md)), and removing a
security control to silence a build error is the wrong trade. The
discipline is now written down in
[`CONTRIBUTING.md`](../../CONTRIBUTING.md).

## Still open

Unchanged from v1.0.0, and still true:

- Contact placeholders in `SECURITY.md`, `CODE_OF_CONDUCT.md`,
  `docs/governance/privacy.md` and `docs/governance/incident-response.md`
  must be filled before publication.
- The seeded syllabus-check entry records transcription provenance only; no
  live check of the external OSN/IOI sources has been performed.
- `osn report --by topic|week` exits 2 pending a problem-to-topic resolver
  the corpus cannot supply.
- `complexitySelectionAccuracy` is a TLE-based proxy, not a direct
  measurement.
- The week-to-topic-family mapping is an editorial inference, not source
  text.
