# 6. Sistem Evaluasi, Rubrik, dan KPI

## 6.1 Bobot internal

| Komponen | Bobot | Evidence |
| --- | --- | --- |
| Computational thinking & konsep | 20% | Tracing, modeling, quiz logika/complexity. |
| Problem solving & algorithm selection | 25% | Constraint analysis, alasan pemilihan algoritma, subtask plan, proof sketch. |
| Implementation correctness | 25% | Accepted rate, edge-case coverage, error taxonomy, code clarity. |
| Contest performance | 20% | Score, time-to-first-correct, partial score, time allocation, stability. |
| Upsolve & learning process | 10% | Re-solve, error log, ability to explain solution without editorial. |

## 6.2 Status penyelesaian soal

| Kode | Makna | Tindak lanjut |
| --- | --- | --- |
| A | Solved independently | Review singkat; tandai pola transfer. |
| B | Solved after hint | Re-solve 3-7 hari tanpa hint. |
| C | Solved after editorial/solution | Wajib reimplement + jelaskan invariant/state + re-solve terjadwal. |
| D | Unsolved/blocked | Diagnosis gap: konsep, modeling, complexity, implementation, debugging. |

## 6.3 KPI dashboard mentor

| Metrik | Tujuan penggunaan |
| --- | --- |
| A/B/C/D per topic | Mengukur independensi dan dependency pada bantuan. |
| Time-to-first-correct | Mengukur kecepatan modeling dan implementasi. |
| WA/TLE/RE frequency | Mengidentifikasi failure mode teknis. |
| Upsolve completion | Mengukur pembelajaran setelah contest. |
| Repeat-solve retention | Memastikan solusi tidak hanya dihafal dari editorial. |
| Complexity-selection accuracy | Mengukur kemampuan membaca constraint. |
| Contest time allocation | Menilai strategi pemilihan soal dan keputusan berhenti/pindah. |
